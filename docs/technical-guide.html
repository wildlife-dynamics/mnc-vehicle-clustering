Trajectory filter

Relocations To Trajectory keeps only track segments within these limits. Anything outside them is treated as a GPS error and dropped before the time density and cluster detection run.

SettingValue
max_speed_kmhr75 (previously 100)
min_speed_kmhr0.025
max_time_secs21600 (6 hours)
min_time_secs1

Form overrides

spec.yaml has an rjsf-overrides block that changes the run form:

OverrideWhat it does
get_subject_group.properties.subject_group_nameA drop-down instead of free text. EarthRangerEnumResolver (type: subject_group_name) fills it with the subject group names of the site picked in er_connection (depends_on: properties.er_connection.properties.data_source.properties.name).
uiSchema.ui:orderShows the form sections in this order: workflow details, time range, EarthRanger connection, basemaps, subject group. The connection comes before the subject group, so the drop-down has a site to load from.

Ecoscope Studio's designer doesn't write the properties override, so spec.yaml is maintained by hand. Saving the design from Studio again replaces the spec and drops it.

Recompiling

spec.yaml is the source; ecoscope-workflows-vehicle-clustering-workflow/ is generated from it by wt-compiler. Recompile after changing the overrides: the form schema is part of the generated package.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh vehicle_clustering --all
